    Software Scanner

    Each Windows PC scans its own software twice a day and uploads the list to Supabase under its machine name. A Streamlit dashboard reads that online database and shows every PC with charts, flagging blacklisted software like VPN and torrent clients.

    Overview

    The system has two programs, and each one lives where it has to run.

    ProgramRuns onJob
    SoftwareScanner.exe
    built from software_scanner.py    		Every PC you want to monitorInstalls itself, then scans and uploads twice a day through Task Scheduler. Needs no Python on the PC.
    regquery.pyStreamlit Cloud, or your PC for testingReads Supabase and shows the dashboard. It never scans anything itself.

    They can't be one file. The scanner has to run on each PC even when nobody has the dashboard open, while the dashboard runs on a Linux server with no Windows registry. Keeping them apart also means the powerful secret key never leaves the PCs.

    What gets collected

    • Machine name from the hostname command, for example DESKTOP-PDHPTQT.
    • Software names from reg query HKLM\SOFTWARE, taking the part after the last backslash of each key.
    • Scan time in UTC.

    Good to know. HKLM\SOFTWARE lists top-level keys, which are mostly vendor or system names like Microsoft or Classes, not every installed program. Only install the scanner on PCs you own or have permission to monitor.

    Change detection

    Every scan updates the computers row, which keeps last_scan fresh so the dashboard knows the PC is alive. A scan_history row is only added when the list is different from last time. Thirty identical scans therefore produce one history row, not thirty.

    The schedule

    The task runs at 09:00 and 21:00 as the SYSTEM account, so it works without anyone logged in. It also runs on battery, and a scan missed while the PC was off runs as soon as it's back on.

    The database

    Supabase holds two tables. Software lists are stored as JSON arrays.

    Tables

    TableColumnsRows
    computerscomputer_name (primary key), software, last_scanOne per PC, always the newest scan
    scan_historyid, computer_name, software, scanned_atOne per change, used for alerts and the history chart

    Keys and access

    KeyStarts withLives inReadWrite
    Secret key, one per PCsb_secret_C:\ProgramData\SoftwareScanner\config.jsonYesYes
    Publishable keysb_publishable_Streamlit secretsYesNo

    Row Level Security only lets the publishable key read, so even if someone finds it they can't change or delete scans. Secret keys bypass those rules, which is why they stay on the PCs.

    Setup SQL

    Run this once in Supabase under SQL Editor → New query.

    create table computers (
  computer_name text primary key,
  software      jsonb not null,
  last_scan     timestamptz not null default now()
);

create table scan_history (
  id            bigint generated always as identity primary key,
  computer_name text not null,
  software      jsonb not null,
  scanned_at    timestamptz not null default now()
);

create index on scan_history (computer_name, scanned_at desc);

alter table computers    enable row level security;
alter table scan_history enable row level security;

create policy "Dashboard can read computers"
  on computers for select to anon using (true);
create policy "Dashboard can read history"
  on scan_history for select to anon using (true);

grant select on computers, scan_history to anon;
grant all on computers, scan_history to service_role;

    Adding another PC

    1. In Supabase, open Project Settings → API Keys → Secret keys, click New secret key, and name it after the PC, for example lab_pc_02.
    2. Copy SoftwareScanner.exe to the PC with a USB stick or OneDrive.
    3. Double-click it and click Yes on the administrator prompt.
    4. Choose 1. Install and paste the key.
    5. Open the dashboard. The PC appears in the Computer dropdown.

    The menu

    OptionWhat it does
    1. Install (or update the key)Test scan, save key, lock folder, copy the exe, create the task. Run it again to change the key.
    2. Scan nowUploads immediately, without waiting for the schedule
    3. UninstallRemoves the task and the saved key. Old scans stay in Supabase.

    What the installer protects

    • Wrong keys are caught by the test scan before anything is saved.
    • The key file sits in a folder only SYSTEM and Administrators can open, so normal users on that PC can't read it.
    • Laptops still scan on battery, and missed scans catch up when the PC turns on.

    Keys and security

    One secret key per PC

    Give every PC its own named secret key. If a PC is lost or no longer yours, delete just its key in Supabase and it can't upload any more, while every other PC keeps working.

    Separate keys let you cut off one PC. They don't limit what a key can do, since every secret key still has full access to the database until it's deleted.

    If a secret key leaks

    1. Create a new secret key in Supabase.
    2. On that PC, run SoftwareScanner.exe, choose 1, and paste the new key.
    3. Check the log shows entries sent.
    4. Delete the old key in Supabase. Do this last, or the PC's scans fail in between.

    Scans already in the database aren't affected, and neither is the dashboard.

    Useful commands

    Run these in Command Prompt as administrator on the PC.

:: check the task and its last result (0 = success)
